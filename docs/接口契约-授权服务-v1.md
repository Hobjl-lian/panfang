## 0. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `https://<你的域名>/v1`（开发期形态：`http://<本机局域网IP>:8787/v1`，App 端做成可配置项） |
| 传输 | HTTPS（上线必须；开发期允许明文 HTTP 走局域网） |
| 编码 | 请求/响应均 `application/json; charset=utf-8`；所有二进制一律 **base64（标准字母表，无换行）** |
| 鉴权 | 客户端：`Authorization: Bearer <license_token>`；管理端：`Authorization: Bearer <admin_token>`（独立密钥，仅后台持有） |
| 时间 | 全部 Unix 秒（整数），UTC |
| 错误格式 | `{"error": "<机器码>", "message": "<中文说明，可直接展示给用户>"}` |
| 幂等 | 有副作用的写操作（redeem/activate）请求可带 `request_id`（客户端随机 16B base64），服务端 24h 内同 id 重复请求返回首次结果 |

### 0.1 错误码表（机器码 → 平台文案）

| error | HTTP | 前端/App 文案（设计稿口径） |
|---|---|---|
| `code_invalid` | 404 | 兑换码不存在，请检查是否输错 |
| `code_used` | 409 | 这个兑换码已经被使用过了 |
| `code_expired` | 410 | 兑换码已过期 |
| `code_disabled` | 403 | 兑换码已被停用 |
| `product_offline` | 403 | 该表盘已下架 |
| `device_limit` | 403 | 已达到设备数量上限（2 台），请先在设置中解绑 |
| `token_invalid` | 401 | 登录状态已失效，请重新兑换 |
| `license_revoked` | 403 | 该授权已被回收 |
| `bad_request` | 400 | 请求有误（附 message 说明） |
| `rate_limited` | 429 | 操作太频繁，请稍后再试 |
| `server_error` | 500 | 服务暂时不可用 |

### 0.2 冻结的密码学参数（不可在实现中擅自更换）

| 参数 | 值 |
|---|---|
| 内容加密 | `AES-256-GCM`，CEK = 32B 随机，`file_nonce` = 12B 随机（每文件固定，随元数据下发） |
| 设备密钥 | `X25519`（App 端生成，私钥存 Android Keystore；公钥 32B raw，base64 上传） |
| 密钥包裹 | ECIES：`ECDH(server_ephemeral_priv, device_pub)` → `HKDF-SHA256`（salt=16B 随机，info=`"wf-cek-wrap-v1"`）→ `KEK_ecdh`(32B) → `AES-256-GCM(KEK_ecdh, wrap_nonce, CEK)` |
| 直链签名 | HMAC-SHA256（服务端密钥），参数 `file_id + exp + uid`；有效期 **300 秒** |
| 文件哈希 | `SHA-256`，十六进制小写。`sha256_plain` 用于客户端解密后校验；`sha256_cipher` 用于下载完整性 |
| 兑换码存储 | 服务端只存 `SHA-256(code)`；明文仅生成时导出 CSV |
| license_token | **不透明随机串**（32B base64url），服务端表存储，有效期 30 天，可即时吊销（不用 JWT） |

### 0.3 客户端处理不变量（App 侧实现要求）

1. 付费密文**永不写明文到磁盘**；解密在内存完成，产出直接喂 `device_install_payload(data_b64)`。
2. 解密后必须校验 `sha256_plain`，不一致则中止并提示「文件校验失败」。
3. 任何一步失败都要能让用户重试，且不消耗兑换码/授权（redeem 只在成功建授权后才标记码已用）。

## 1. 客户端端点

### 1.1 POST /v1/redeem —— 兑换

请求：

```json
{
  "code": "AWOS-7K3M-9PQR-2XTV",
  "mi_user_id": "1234567890",
  "device_fp": "9f86d081...（sha256 hex，见 §1.1.1）",
  "device_pubkey": "base64(32B X25519 公钥)",
  "device_name": "Xiaomi 手环 10",
  "request_id": "base64(16B 随机)"
}
```

响应 200：

```json
{
  "license_token": "base64url(32B)",
  "expires_at": 1790000000,
  "subject": { "mi_user_id": "1234567890", "display": "8888" },
  "products": [
    {
      "product_id": "awos",
      "name": "AWOS 照片表盘",
      "variants": [
        { "variant_id": "awos@band10", "device_model": "xiaomi_band_10",
          "screen": [212, 520], "latest_version": "3.0",
          "latest_sha": "9d3f…（整行内容指纹，见 §1.2 说明）",
          "packages": [
            { "file_id": "f_9c1", "file_name": "awos_v3_p1.bin",
              "watchface_id": "145604789600", "version": "1.1.1",
              "sha256_plain": "…", "size": 734521 }
          ] }
      ],
      "activations_used": 1, "activation_limit": 2
    }
  ]
}
```

- 校验顺序：`code` 格式 → 哈希命中 → 未用/未过期/未停用 → 产品在售 → 设备数上限。
- 成功后服务端：标记码已用并绑定 subject；登记 `device_fp/device_pubkey` 为一次 activation；签发 token。
- **同 subject 再次兑换同一产品的新码**：不报错，视为补充授权（设备数上限仍生效）。

#### 1.1.1 device_fp 的计算（冻结）

```
device_fp = hex(sha256( android_id_or_app_uuid + "|" + Build.MODEL ))
```

说明：取 Android `Settings.Secure.ANDROID_ID`（无需权限）；若为空退化为 App 自生成并持久化的 UUID。服务端**不解析**该值，只做等值比较与去重。

### 1.2 GET /v1/me —— 我的授权

```
GET /v1/me                                  [Bearer]
→ 200 { "subject": {...}, "products": [ 同 redeem 的 products ],
        "activations": [ { "device_fp": "...", "device_name": "...", "product_id": "awos",
                           "activated_at": 1789000000, "last_seen_at": 1789100000 } ] }
```

用途：设置页「我的授权/设备管理」；模式 B 下单后 App 轮询此接口即可自动激活。

> **`latest_sha` = 整行内容指纹**（v1.4 新增）：把该设备行最新版本（`is_latest=1`）的全部包
> 按 `files.sort_order, id` 顺序取出 `sha256_plain`，用 `|` 连起来再 sha256。
> 老 App 用它判「有没有新版本」；新 App（v1.7 起）优先用逐包的 `packages`。
> 没有包体的设备行为 `null`。算法两侧必须一致 —— 改一边就要改另一边。
>
> **`packages` = 逐包指纹**（v1.7 新增，2026-10-17）：最新版本每个包一条，含 `file_id` /
> `file_name` / `watchface_id` / `version` / `sha256_plain` / `size`。
> App 在安装时按 `watchface_id` 记下每个包当时的 `sha256_plain`（本机安装快照），之后逐包比较：
> **只有 sha 变了的包才标「有更新」并下载**，没变的包不再重传。
> 没装过的新包标 `new`；老安装记录没有快照时，App 会先用本机留档还原，还原不到才退回整行 `latest_sha`。

### 1.3 POST /v1/activate —— 换设备/新增设备

```json
{ "product_id": "awos", "device_fp": "...", "device_pubkey": "base64(32B)", "device_name": "..." }
```

- 成功 200 `{ "activation": {...}, "activations_used": 2, "activation_limit": 2 }`
- 超限：403 `device_limit`。
- 每台设备每次下载都必须用**本机私钥可解**的包裹；因此换机后旧设备仍占额度，需解绑腾位置。

### 1.4 GET /v1/manifest —— 版本清单

```
GET /v1/manifest?product_id=awos&variant_id=awos@band10     [Bearer]
→ 200 {
  "product_id": "awos", "variant_id": "awos@band10",
  "latest_version": "3.0",
  "versions": [
    { "version": "3.0", "released_at": 1789000000, "notes": "新增渐变配色",
      "files": [ { "file_id": "f_9c1", "file_name": "awos_v3.bin", "size": 734521,
                   "watchface_id": "145604789600", "version": "1.1.1",
                   "sha256_plain": "...", "sha256_cipher": "..." } ] },
    { "version": "2.0", ... }
  ]
}
```

- 无授权：403 `license_revoked`/`token_invalid`；产品已下架：403 `product_offline`。
- App 默认取 `latest_version` 的**第一个文件**安装；多文件（一个版本含多个 .bin）时按 `files` 顺序逐个安装。

### 1.5 POST /v1/download —— 取直链 + 包裹密钥

```json
{ "file_id": "f_9c1", "device_fp": "9f86d081...（可选；多设备账号必填）" }
```

> v1.1：新增可选 `device_fp`。登录态下该账号可能有多台激活设备，包裹密钥必须指向目标设备；
> 只有一台激活设备时可省略（服务端取最近活跃的那台）。

响应 200：

```json
{
  "url": "https://cdn.<域名>/dl/f_9c1.enc?exp=1790000300&uid=s_123&sig=...",
  "expires_at": 1790000300,
  "file": { "file_id": "f_9c1", "size": 734521, "sha256_plain": "...", "sha256_cipher": "..." },
  "alg": "AES-256-GCM",
  "file_nonce": "base64(12B)",
  "key_wrap": {
    "alg": "X25519-HKDF-SHA256-A256GCM",
    "epk": "base64(32B 服务端临时公钥)",
    "salt": "base64(16B)",
    "wrap_nonce": "base64(12B)",
    "cipher": "base64(48B = 32B CEK + 16B tag)"
  }
}
```

客户端流程（冻结）：

```
1. GET url → 密文（内存缓冲；如需分片下载则落 .enc 临时文件，本身就是密文）
2. 校验 sha256_cipher
3. KEK_ecdh = HKDF-SHA256(ikm = ECDH(device_priv, epk), salt, info="wf-cek-wrap-v1")
4. CEK = AES-256-GCM-open(KEK_ecdh, wrap_nonce, key_wrap.cipher)
5. plain = AES-256-GCM-open(CEK, file_nonce, ciphertext) → 校验 sha256_plain
6. device_install_payload(plain, "bin")
```

- 服务端每次调用生成**新的临时 X25519 密钥对**，用完即弃（前向保密；抓包重放只能拿到过期包裹）。
- 每次下载记审计日志（subject/设备/文件/IP/UA），供风控与泄露追溯。

### 1.6 POST /v1/unbind —— 解绑设备（M4，可延后）

```json
{ "product_id": "awos", "device_fp": "..." }
```

- 默认规则：同一 subject 对同一 product 每 30 天可自助解绑 1 次，超出需人工（返回 403 `device_limit` + message 提示联系开发者）。

**上传即加密**（服务端）：明文只以流形式过内存 → 生成 CEK → 写密文到存储（本地目录或 S3 兼容）→ `files.cek_wrapped` 入库。明文不落盘。

**照片表盘判定**（2026-10-15 加）：上传时按 `.bin` **内容**判 —— 亮屏样式的 `backImageId` 高字节 `0x82`
（息屏/普通背景为 `0x80`），写入 `files.photo_album`；同一批写入的还有 `files.watchface_id`（每个包自己的
表盘 id，一个设备行可能有 2 个包）。管理页可按人工判定覆盖，值存 `photo_album_overrides`（按 `watchface_id`，
重传包体不丢）。**这是内容判据、不看表盘名字** —— 名字里没有「照片表盘」的（如《OS27模块》）一样能判出来。

## 3. 数据存储最低要求（实现自由，语义冻结）

- `codes.code_hash`（唯一）+ `status` + `product_id` + `batch_id` + `expires_at` + `used_at` + `used_by_subject`
- `activations(subject_id, product_id, device_fp, device_pubkey, status, last_seen_at)`，唯一键 `(subject_id, product_id, device_fp)`
- `files.cipher_path`（存储键）、`files.file_nonce`、`files.cek_wrapped`（KEK 包裹）
- `download_logs(file_id, subject_id, device_fp, ts, ip, ua)`
- 所有时间 UTC 秒；所有 hash 小写 hex。

## 4. 爱发电对接（模式 A 先行）

- **模式 A（现在）**：管理端 `/admin/codes/batch` 导出 CSV（一行一个明文码）→ 手工粘贴到爱发电商品「自动回复 → 随机发放」卡密库。App 侧无感知。
- **模式 B（M3）**：`POST /webhook/afdian` 仅作「有新订单」信号；服务端**必须**再调爱发电订单查询接口确认 `status=2` 且金额/商品匹配后才发货/激活；失败一律拒绝（fail-closed）。字段与验签细节在实施该阶段时补入本契约 v1.1。
- **订单归属（v1.6 起，2026-10-16）**：一笔订单的权益只归属一个主体。首次同步处理该订单时把归属写进 `afdian_orders.granted_subject_id`；之后无论经哪条路径（定时对账、绑定补发 `sync_after_bind`、全量补拉）再次遇到它，只要当前绑定主体不是归属主体，一律拒绝开通（记 `SyncSummary.replayed` 并打日志）。**换绑只改变"以后新订单归谁"，不搬走、也不复制已有资源**；买家换小米账号要迁移资源走管理端人工处理。退款/撤单的收回不受影响（按 `licenses.source = 'afdian:<订单号>'` 全局收回）。
